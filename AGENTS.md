# Project Rules

- **Deck terminology:** Before changing anything under `Pocket Stack/Features/Deck`, read [`DECK_TERMINOLOGY.md`](DECK_TERMINOLOGY.md) and use its definitions for NoteFan, preview, length/depth, overlap, direction, and alignment.
- **Direct-edit discipline:** When the user names an exact file, symbol, value, or one-line operation, make only that requested change. Do not broaden it into an audit, refactor, architecture change, or unrelated verification. Once the editing tool reports success, stop unless compilation is required by these rules or the user explicitly requests further validation.
- **Latest instruction wins:** Treat the user's newest correction, prohibition, or stop request as an immediate override of an earlier plan. Stop the superseded activity before doing anything else; do not reinterpret a plain request into a different technical operation.
- **Computer-use privacy:** If the user says to stop, disable, or not use computer use, immediately stop all screen capture, UI automation, app control, and related runtime interaction for the remainder of the task. Do not substitute an install/uninstall check for this instruction, and do not call the capability again unless the user explicitly re-enables it.
- **Completion evidence:** Never report a runtime bug as fixed based only on successful compilation or source inspection. Report it as verified only after the failing behavior has been reproduced and the same scenario passes after the change. If runtime verification is forbidden or unavailable, say that the change compiles but remains runtime-unverified.
- **Regression gate:** A fix is not complete if it introduces a new warning, error, feedback loop, layout recursion, or behavior regression in the affected flow. Treat such output as evidence that the approach failed; do not present the task as completed.
- **Diagnostic logging:** When asked to add logs, add the smallest set of observational logs at the named decision points. Logging must not rewrite control flow, alter timing/state, or bundle a speculative fix. Keep a diagnostic-only edit narrowly scoped and state exactly which events it records.
- Never add, generate, or modify unit tests in this project.
- Do not run unit tests. Validation is complete once the affected targets compile successfully.
- **Warning Policy:** Fix warnings caused by the code being changed and warnings explicitly identified by the user. Do not expand the task to unrelated project or toolchain warnings. Never suppress diagnostics or add workaround code; fix the relevant root cause using current Swift, SwiftUI, and AppKit best practices.
- **Scroll Layouts:** When placing `PocketNoteEditorView` inside a `ScrollView` (such as in `LibraryView`), you MUST pass `scrolls: false` so that it expands to fit its content (`fitsContent`). Do not use `.frame(minHeight: ...)` or fixed frames that constrain it into an inner-scrolling box.
